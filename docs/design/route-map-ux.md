# 버스 번호에서 시작하는 정류장 선택

2026-09-17 · UI/UX 제안 · 제품 코드에는 아직 반영하지 않음

## 권장 방향

처음 설정할 때 **버스 번호 검색 → 노선·방향 확인 → 지도에서 정류장 선택 → 위젯에 저장**을 기본 흐름으로 제공한다. 버스 번호를 모르는 사람을 위해 기존 **정류장으로 찾기**도 검색 화면에서 같은 수준으로 접근할 수 있게 둔다.

지도의 목적은 정류장 이름을 외우게 하는 대신, 내가 타는 위치와 도로의 어느 쪽인지를 확인하게 하는 것이다. 지도만 제공하면 정밀한 터치, 위치 권한, 지도 해석 능력을 요구하므로 **지도와 노선 순서 목록은 같은 선택 상태를 공유**한다.

- 기존 사용자: 저장된 위젯 설정 화면이 홈. 수정할 때만 선택 흐름에 진입한다.
- 신규 사용자: 버스 검색이 기본. 위치 권한은 시작 조건이 아니다.
- 저장 단위: 현재와 같이 **정류장 하나 + 그 정류장을 지나는 노선 최대 4개**를 유지한다.
- 지도에서 고른 노선은 마지막 저장 화면에 미리 선택한다. 다른 노선을 더해도 정류장은 바뀌지 않는다.

## 화면과 행동

| 화면 | 가장 먼저 보여줄 정보 | 주요 행동 | 다음 단계 조건 |
|---|---|---|---|
| 1. 버스 찾기 | 버스 번호 입력, 최근 검색, 정류장 검색 전환 | 검색 결과의 노선 선택 | 지역·기종점으로 노선을 식별할 수 있음 |
| 2. 탈 정류장 선택 | 노선 번호, 목적지로 표현한 방향, 지도와 목록 전환 | 지도 핀 또는 목록 항목 선택 | 선택한 방향의 유효한 정류장임 |
| 2-1. 정류장 미리보기 | 전체 정류장 이름, 정류장 번호, 방향, 다음 정류장 | ‘이 정류장에서 탈게요’ | 노선과 정류장 관계가 확인됨 |
| 3. 위젯 설정 확인 | 정류장·방향·선택 노선, 같은 정류장의 추가 노선 | ‘위젯에 저장’ | 1~4개 선택, 식별·방향 모호성 없음 |
| 4. 저장 완료 | 저장한 정류장·노선, 위젯 추가 안내 | 홈으로 복귀 | 영속 저장 성공 후 완료 표시 |

### 검색

- ‘버스 번호로 찾기 / 정류장으로 찾기’ 전환. 기존 정류장 검색은 유지한다.
- 노선 결과: 큰 번호 + ‘경기 · 직행좌석’ 같은 지역·유형 + 기종점. 동명 노선을 숫자만으로 합치지 않는다.
- 숫자 외에 M, N, 하이픈 등도 입력할 수 있는 키보드를 사용한다.
- 검색 대기 300ms, 오래된 응답 폐기. 로딩·검색 결과 없음·재시도를 분리한다.
- 뒤로 돌아오면 검색어와 결과 스크롤을 유지한다.

### 지도와 방향

- 노선 선택 후 지도는 해당 노선만 표시한다. 다른 시내 모든 정류장 핀을 함께 뿌리지 않는다.
- ‘상행 / 하행’ 대신 ‘○○ 방면’을 쓴다. 경유지나 지선이 다르면 보조 설명을 붙인다.
- 최초에는 어느 방향도 확정하지 않는다. 양방향을 볼 수 있지만 **방향을 고르기 전 저장할 정류장을 확정하지 않는다**. 시안에서는 방향 버튼을 먼저 누르게 한다.
- 방향 변경 시 호환되지 않는 정류장 선택을 해제하고, ‘방향이 바뀌었어요. 탈 정류장을 다시 골라 주세요’를 알린다. 반대편 승강장 자동 선택 금지.
- 선택한 핀: 크기·체크 표시·이름 라벨. 노선선에는 진행 화살표. 색만으로 상태를 구분하지 않는다.
- 촘촘한 핀은 확대하거나 목록으로 선택한다. 정류장 좌표가 도로의 어느 쪽인지 구분하기에 부정확하면 지도만 보고 확정하게 하지 않는다.
- ‘노선 전체’, ‘내 위치’, ‘목록으로 보기’를 제공한다. 실제 앱에서는 확대·축소와 지도 이동도 가능하다.
- 위치는 ‘내 위치’를 누를 때 요청한다. 거절 시 전체 노선과 검색·목록을 그대로 쓸 수 있다. 가까운 정류장은 추천만 하고 선택하지 않는다.
- 거리 표시를 제공한다면 직선거리임을 명시한다. 보행 경로 계산 없이 도보 시간을 만들어 내지 않는다.

### 정류장 카드와 최종 저장

- 지도 아래 카드는 정류장명 전체 → 정류장 번호 → 방면 → 다음 정류장 → 확인 버튼 순서다.
- 정류장 번호는 표시 정보다. 서울·경기 간 같은 5자리 번호를 같은 장소로 취급하지 않는다.
- 다음 정류장은 데이터가 있을 때만 표시한다. 종점이면 ‘이 방향의 마지막 정류장’으로 표시한다.
- 바텀 시트는 접힌 상태/확장 상태를 제공하되 드래그 외에 ‘목록으로 보기’ 버튼으로도 접근 가능해야 한다.
- 확인 화면에서 같은 정류장의 다른 버스를 추가 선택한다. 최대 4개이며 이미 선택한 버스를 다시 해제할 수 있다.
- 다른 방향의 버스를 추가할 때는 각 노선의 방향을 따로 보여준다. 서로 다른 방향을 하나의 공통 방면 문구로 오인시키지 않는다.
- 저장 중에는 중복 탭을 막고, 실패 시 선택을 보존한 채 재시도한다.
- 기존 설정을 수정할 때는 최종 저장까지 원래 설정을 유지한다. 다른 정류장으로 바뀌면 저장 버튼 위에 ‘기존 ○○ 정류장 설정을 이 설정으로 바꿉니다’를 표시한다.
- 뒤로 가기에는 선택 초안을 보존한다. 편집 전체를 취소할 때만 변경사항 폐기 여부를 묻는다.

## 화면 표현

기존 SwiftUI 앱의 파란색과 시스템 서체를 유지한다. 숫자와 정류장명이 중심이며 지도 위의 장식·반투명 효과를 줄인다.

| 항목 | 기준 |
|---|---|
| 기본 서체 | iOS 시스템 서체, 한국어 시스템 폴백, 본문 17pt |
| 색 | 기본 강조 #2563EB, 본문 #14213D, 보조 본문 #53627A, 배경 #F5F7FC |
| 어두운 모드 | 어두운 표면 + 밝은 본문 + 밝은 강조 글자; 버튼은 대비가 확보된 별도 색 사용 |
| 간격 | 4/8pt 배수, 화면 여백 20pt, 카드 16~20pt |
| 터치 | 최소 44×44pt, 이웃 터치 영역 간 충분한 간격 |
| CTA | 한 화면에서 채워진 기본 버튼 하나, 세로 52pt 이상 |
| 전환 | 선택/화면 전환 150~250ms, 동작 줄이기에서 움직임 최소화 |
| 접근성 | 색 외 체크·텍스트, 논리적인 VoiceOver 순서, 확대 글씨에서 줄바꿈 |

VoiceOver 핀 예: ‘테크노마트앞.강변역 D, 정류장 번호 05267, 하남 방면, 선택됨’. 목록으로 지도와 같은 작업을 끝낼 수 있어야 한다. 큰 글씨에서는 지도 높이를 고집하지 않고 목록·확장 카드에 우선순위를 준다. 저장 버튼은 안전 영역을 준수하고 스크롤 마지막 항목을 가리지 않는다.

## 예외 상태

| 상황 | 사용자에게 보여줄 내용과 회복 방법 |
|---|---|
| 위치 권한 거절/현재 위치를 못 찾음 | ‘위치 없이도 정류장을 고를 수 있어요’ + 노선 전체/목록 유지 |
| 지도 타일만 실패 | ‘지도를 불러오지 못했어요’ + 정류장 목록 + 지도 재시도 |
| 노선·정류장 데이터 실패 | 로딩 중 저장 차단, 오류 설명 + 재시도, 원래 위젯 설정 유지 |
| 도착 예정 버스 없음 | ‘현재 도착 정보가 없어요’; 운행 노선과 정류장 관계가 확인되면 저장 가능 |
| 저장된 캐시만 있음 | 마지막 갱신 시각과 오프라인 상태 표시. 확인 불가한 새 조합 저장 차단 |
| 같은 정류장을 한 노선이 여러 번 경유 | 방문 순서·경유지로 구분. 방향별 도착 정보를 보장할 수 없으면 선택 제한과 이유 표시 |
| 노선 폐지·정류장 이동 | 기존 선택 상태에서 재선택 안내. 이름이 비슷한 다른 정류장으로 자동 교체 금지 |

## 구현 전에 필요한 데이터

현재 `StationSearchView`는 정류장 검색, `RouteSelectionView`는 해당 정류장의 최대 4개 노선 선택을 담당한다. `WidgetConfigurationData`는 stationId/stationName/routeIds만 저장한다. 현재 백엔드의 정류장 검색·도착정보만으로는 노선 전체 지도와 방향 선택을 완성할 수 없다.

필요한 기능:

1. 지역을 구분하는 노선 검색: 노선 식별자, 번호, 지역, 유형, 기종점.
2. 노선별 순서가 있는 정류장: 정류장 식별자, 좌표, 순번, 방향·회차 정보.
3. 지도 노선선: 가능하면 실제 경로 좌표. 정류장 사이를 직선으로 연결할 때는 실제 도로 경로로 오해하지 않도록 한다.
4. 선택의 유효성 확인: 해당 정류장을 해당 노선·방향이 실제로 경유하는지 확인.
5. 반복 경유 대응: `노선 + 정류장 + 방문 순번`을 유지하고 위젯·도착정보·Live Activity까지 일관되게 연결. 현재 저장 모델만으로 방향이 보장된다고 가정하지 않는다.

API 설계 시 `routeId`도 제공기관을 포함한 고유 식별자를 사용한다. `stationId`는 기존 서울 ID와 `gg:` 접두어를 보존한다. 표시용 번호나 정류장 이름으로 조인하지 않는다. 방향과 순번을 공급기관이 명확히 제공하지 않는 경우 프론트에서 임의 추측하지 않는다.

승인 확인 대상은 **서울특별시_노선정보조회 서비스**, **경기도_버스노선 조회**다. 기존 정류소·도착정보 서비스 승인과 별도 서비스다. 공식 문서상 서울 경유 정류장 조회와 경기 경유 정류장·노선형상 조회가 있으므로 연동 검증 후 구현한다.

- [서울특별시 노선정보조회 서비스](https://www.data.go.kr/data/15000193/openapi.do): 노선 검색과 `getStaionByRoute` 경유 정류장 조회.
- [경기도 버스노선 조회](https://www.data.go.kr/data/15080662/openapi.do).
- [GBIS 노선번호 조회](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRoute).
- [GBIS 노선 경유 정류소 조회](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteStation): 순번·좌표·회차 관련 필드.
- [GBIS 노선 형상정보 조회](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteLine).

지도 구현은 기존 SwiftUI와 연결하기 쉬운 MapKit을 후보로 둔다. 한국 승강장 수준의 가독성과 좌표 정확도를 실제 기기에서 확인한 뒤 확정한다. 다른 지도 SDK로 바뀌어도 선택 상태와 목록은 독립적으로 유지한다.

## 단계별 적용과 평가

1. 노선 검색·경유 정류장·방향 데이터 검증. 9304 / 05267 사례와 같은 번호의 다른 지역 정류장, 지선·회차 노선을 포함한다.
2. 기존 정류장 검색을 유지하면서 버스 검색과 지도/목록 선택을 추가한다. 처음에는 방향을 확실히 식별할 수 있는 노선을 대상으로 한다.
3. 반복 경유의 방향별 도착정보까지 일치하도록 저장 모델과 위젯·Live Activity를 확장한다. 검증되지 않은 방향 선택을 완성된 기능으로 노출하지 않는다.
4. 실사용 평가: 9304 강변역 정류장 설정, 반대편 승강장 구분, 위치 권한 거절 후 설정, 같은 번호의 다른 지역 노선 선택, 큰 글씨·VoiceOver로 저장.

측정할 항목은 설정 완료율, 설정 시간, 저장 직후 정류장/방향 수정 비율, 지도↔목록 전환 비율이다. 현재 흐름 대비 개선 여부를 측정하며 목표 수치를 검증 없이 성과로 제시하지 않는다.

## 시안 범위

[클릭 가능한 HTML 시안](route-map-prototype.html)은 설치 없이 브라우저에서 열린다. 버스 검색 → 방향 선택 → 지도/목록 선택 → 추가 노선 선택 → 저장 완료를 체험할 수 있다. 어두운 모드·큰 글씨·위치 거절 상태도 확인할 수 있다.

**지도·정류장 순서·방면·추가 노선은 인터랙션 설명용 예시**다. 실제 운행 정보나 좌표를 검증한 지도는 아니다. 데이터 요청·실제 위치 권한 요청·설정 영속 저장은 하지 않는다. 시안의 정류장 검색은 예시 두 건만 제공하며 실제 앱의 검색을 대체하지 않는다.

HTML 레이아웃과 클릭 흐름은 브라우저에서 검증한다. iOS Dynamic Type 최대 크기, VoiceOver, 지도 제스처, 실제 권한창, 안전 영역, 실제 기기 성능 검증은 SwiftUI 구현 후 별도로 수행해야 한다.

시안 검증 결과: Chrome에서 검색·방향 변경 시 선택 해제·지도/목록 선택 공유·최대 4개 제한·저장 완료·뒤로 가기·위치 거절 예시를 확인했다. 375×812, 812×375, 768×1024, 1024×768에서 밝은/어두운 모드와 기본/22px 본문 조합의 가로 넘침 및 버튼 최소 44px를 확인했다. 주요 본문·보조 본문·강조·버튼 색 조합은 대비 4.5:1 이상이다. 동작 줄이기 미디어 설정에서 시안을 열었으며 JavaScript 실행 오류는 없었다. 22px HTML 본문 검증은 iOS 최대 Dynamic Type 검증을 대신하지 않는다.
