# 버스 번호로 정류장 찾기 — UX 제안

작성일: 2026-09-18 · 상태: 구현·검증 완료

현재 구현은 [정류장 찾기와 버스 선택 UX](route-map-ux.md), 시각 표현은 [공통 디자인 기준](asset-style-guide.md)을 참고한다. 버스 번호로 시작하는 검색 경로의 제안 배경과 구현 기준을 보존한다. 현재 동작은 정류장 UX 문서에도 반영한다.

## 요구사항 구체화

### 원래 요청

> 지금 상황이 정류장 검색을 할때 사용자가 보통 정류장 이름은 잘 모르고 
> 퇴근길에 본인이 타는 버스 검색해서 해당 정류장으로 들어가는 경우가 많아서 이런 경우 어떻게 하면 검색하고 사용하기 편할지 플로우 짜줘 -> 플로우가 직관적이고 간결해야해

### 구체화한 목표

정류장 이름을 모르는 사용자가 버스 번호와 지도상 위치·방향으로 탑승 정류장을 찾아, 즉시 기다리거나 즐겨찾기에 저장할 수 있게 한다.

| 구분 | 내용 |
| --- | --- |
| 사용자 확인 | 회사·정류장 근처에서 바로 검색하는 상황과 집 등 다른 장소에서 미리 등록하는 상황 모두 중요 |
| 사용자 요청 | 직관적이고 간결한 플로우, `docs/design`에 제안 문서로 저장 |
| 설계 제안 | 하나의 검색 흐름 안에서 가까운 정류장과 전체 정류장을 전환 |
| 범위 | 검색 진입, 버스 결과, 탑승 정류장·방향 선택, 대기 시작·즐겨찾기 저장 |
| 성공 기준 | 버스 번호 입력 후 버스 선택 → 정류장 선택 → 기다리기 또는 저장으로 완료. 정류장 이름 입력과 버스 재선택을 요구하지 않음 |

## 핵심 흐름

```text
버스 번호 검색
  → 버스 선택
  → 해당 버스가 서는 정류장을 지도·목록에서 선택
  → 선택 요약 확인 후 기다리기 또는 저장
```

현재 위치는 가까운 후보를 추천하는 데 사용한다. 다른 지역의 정류장도 같은 흐름에서 찾을 수 있도록 전체 노선 접근을 항상 제공한다. 사용 목적을 묻는 사전 질문이나 별도의 방향 선택 화면은 추가하지 않는다.

## 1. 검색창 하나에서 시작

- 검색창 문구: `버스 번호 또는 정류장`.
- 버스 번호를 입력하면 버스 결과를 우선 표시한다. 숫자 정류장 번호도 검색할 수 있도록 결과를 `버스`와 `정류장`으로 구분한다. 입력 전에 검색 종류를 고르게 하지 않는다.
- 같은 버스 번호가 여러 노선에 있으면 `지역 · 기점 ↔ 종점`을 함께 표시한다. 번호가 같다는 이유로 합치거나 자동 선택하지 않는다.
- 정류장 이름으로 검색하면 기존 정류장 선택 흐름으로 연결한다.
- 뒤로 돌아오면 검색어와 결과 목록 위치를 유지한다.

## 2. 버스를 선택하면 “어디서 타세요?”

상단에 선택한 버스 번호를 유지하고, 지도와 목록에는 해당 노선의 정차 정류장을 표시한다.

```text
← 9304번
어디서 타세요?

[노선 지도 + 정류장 표시]
                         [내 위치]

[가까운 정류장]   [전체 정류장]

○○역
△△ 방면 · 다음: □□                 ›
정류장 번호 12-345

○○역
◇◇ 방면 · 다음: ▽▽                 ›
정류장 번호 12-346
```

예시의 정류장·방면·번호는 화면 구조 설명용이며 실제 운행 정보가 아니다.

### 현장에서 바로 찾기

- 유효한 현재 위치와 주변 후보가 있으면 `가까운 정류장`을 먼저 보여준다.
- 가까운 후보부터 정렬하되 가장 가까운 정류장을 자동 선택하지 않는다. 길 건너편 정류장일 수 있다.
- 지도에서 도로·주변 건물과 정류장 위치를 함께 볼 수 있게 한다.
- 위치 권한은 기존처럼 사용자가 `내 위치`를 눌렀을 때 요청한다. 이미 사용할 수 있는 위치가 없으면 전체 보기에서 시작한다.

### 다른 장소에서 미리 등록하기

- `전체 정류장`을 누르면 해당 노선 전체가 보이는 지도와 운행 순서의 정류장 목록을 표시한다.
- 지도를 회사 근처로 확대하거나 목록에서 정류장을 선택할 수 있다.
- 보기 전환 시 버스 선택을 유지한다. 현재 위치와 멀다는 이유로 정류장을 검색 결과에서 제외하지 않는다.
- 주변 후보가 없거나 위치를 사용할 수 없으면 전체 보기로 시작한다. 위치 허용을 검색의 필수 조건으로 만들지 않는다.

### 방향까지 한 번에 선택

- 정류장 항목에 `정류장 이름 → 방면·다음 정류장 → 정류장 번호`를 표시한다.
- 이름이 같은 길 양편 정류장을 구분하고, 같은 정류장을 여러 방향으로 지나는 노선은 탑승 방향별 선택 항목을 제공한다.
- 선택 단위는 단순 정류장 이름이 아니라 해당 버스의 정류장·방향별 경유 항목이다.
- 목록 항목을 누르면 지도에서도 해당 위치를 강조한다. 지도 마커에 여러 탑승 방향이 있으면 하단 목록에서 구분해 선택한다.
- 데이터에 없는 방면, 다음 정류장, 도보 시간은 추정해 표시하지 않는다. 선택 불가 항목은 이유를 알린다.

## 3. 선택한 버스를 유지하고 바로 실행

정류장·방향을 선택하면 같은 화면의 하단 패널에 선택 요약과 실행 버튼을 표시한다.

```text
○○역 · △△ 방면
9304번 선택됨
다음 정류장: □□

[ 9304번 기다리기 ]

즐겨찾기에 추가
다른 버스 함께 선택
```

| 진입 경로 | 주요 버튼 | 보조 행동 |
| --- | --- | --- |
| 일반 검색 | `9304번 기다리기` | 즐겨찾기에 추가 |
| 즐겨찾기 추가 | `즐겨찾기에 추가` | 저장 완료 후 기다리기 |

- 검색한 버스는 해당 정류장·방향으로 미리 선택한다. 같은 버스를 다시 고르게 하지 않는다.
- `다른 버스 함께 선택`은 선택적으로 펼치는 기능으로 둔다. 펼쳤을 때 기존의 최대 4개 버스 선택 정책을 적용한다.
- 별명은 선택 입력이며, 단일 버스 대기를 시작하는 데 입력을 요구하지 않는다.
- 실행 전에 정류장·버스·방향의 유효성을 검증한다. 실패하면 선택을 유지하고 수정 또는 재시도하게 한다.
- 도착정보가 없어도 유효한 탑승 조합은 즐겨찾기에 저장할 수 있다.
- 저장 성공 후 실제 저장된 즐겨찾기 카드를 보여준다.

## 반복 사용

```text
즐겨찾기의 퇴근길 카드 → 버스 기다리기
```

여러 버스를 저장한 경우 기존의 오늘 기다릴 버스 선택 동작을 따른다. 매번 버스 번호나 정류장을 다시 검색하게 하지 않는다.

## 예외와 상태

| 상황 | 화면 동작 |
| --- | --- |
| 위치 권한 거절·위치 조회 실패 | 전체 노선 탐색 유지, 내 위치 사용 불가 안내 |
| 가까운 정류장 없음 | 주변에 해당 노선 정류장이 없다는 안내와 전체 보기 |
| 검색 결과 없음 | 다른 버스 번호·정류장으로 검색하도록 안내 |
| 일부 지역 검색 실패 | 조회된 결과와 함께 누락 가능성·재시도 표시 |
| 노선 또는 정류장 조회 실패 | 선택한 버스 유지, 오류와 재시도 제공 |
| 지도 표시 실패 | 정류장 목록으로 선택 가능하게 유지 |
| 좌표 없는 정류장 | 지도에는 표시하지 않고 목록에서 확인 가능하게 제공 |
| 도착정보 없음 | 도착정보 없음 표시, 임의의 도착 시간 생성 금지 |
| 저장 또는 대기 시작 실패 | 현재 선택과 오류 유지, 재시도 제공 |
| 뒤로 이동 | 검색어·버스·보기 상태·지도 위치·목록 스크롤 복원 |

## 화면 표현 원칙

- 한 화면에는 주요 실행 버튼 하나를 둔다. 전체 정류장 보기와 내 위치는 탐색 조작으로 구분한다.
- 정류장명·방면은 큰 글자 설정에서도 읽을 수 있도록 줄바꿈한다.
- 터치 영역은 최소 44pt로 확보하며 지도와 목록 모두에서 선택할 수 있게 한다.
- 선택 상태는 색상 외에 체크·텍스트로도 표현한다.
- VoiceOver에서 버스 번호, 정류장, 방면, 다음 정류장, 선택 상태를 구분해 읽는다.
- 기존 공통 색상·서체·지도 표현 기준을 적용하고, 하단 버튼이 목록과 안전 영역을 가리지 않게 한다.

## 구현 기반과 후속 검증

현재 코드에는 `/api/v2/routes/search`, `/api/v2/routes/{ref}`, 정류장별 탑승 옵션 조회와 선택 검증 기능이 있다. iOS API 클라이언트에도 버스 검색·노선 상세 조회 함수가 있다. 통합 검색과 `RouteStopFinderView`에서 노선별 정류장 탐색·미리 선택·저장·대기를 연결한다.

가까운 후보는 직선거리 1km 이내를 거리순으로 표시한다. 위치 정확도는 150m 이내, 측정 시각은 120초 이내를 사용한다. 전체 목록은 운행 순서이며 같은 정류장을 여러 번 지나는 경우 경유 식별자별 방면·다음 정류장을 표시한다. 거리 표시를 추가한다면 직선거리와 도보 거리를 구분한다. 실제 서울·경기 공급자 데이터의 조회 가능 범위도 검증한다.

다음 시나리오로 플로우를 확인한다.

1. 회사 근처에서 버스 번호만 아는 사용자가 지도와 방면을 보고 타는 정류장을 선택해 대기를 시작한다.
2. 집에서 같은 버스를 검색한 사용자가 전체 보기로 전환해 회사 정류장을 찾아 저장한다.
3. 위치 권한 없이도 버스 검색부터 정류장 선택·저장까지 완료한다.
4. 이름이 같은 길 건너편 정류장, 같은 번호의 다른 지역 노선, 같은 정류장의 다른 경유 방향을 구분한다.
5. 뒤로 이동·조회 실패 후에도 검색과 선택을 처음부터 반복하지 않는다.

## 검증 기록

- 2026-09-18: iOS 단위 테스트 65개 통과. 버스·정류장 검색의 독립 실패, 검색 취소, 위치 정확도·유효기간, 전체·주변 목록, 동일 정류장의 방향 구분, 미리 선택 유지와 검증 실패를 포함한다.
- 운영 API 읽기 확인: `9304` 검색에서 서울·경기 공급자 모두 정상 응답. `gg:227000040` 상세는 경유 항목 50개, 선택 가능 항목 41개, 방면 2개이며 좌표 누락과 경유 식별자 중복이 없었다. 실제 APNs 대기 등록은 수행하지 않았다.
- iPhone 17 Pro 크기의 iOS 26.5 시뮬레이터: 전체 UI 테스트 24개 통과. 새 검색 흐름 4개와 기존 지도·정류장 선택·즐겨찾기·대기 동작을 포함한다.

- iPhone SE 3세대 크기(375pt), iOS 26.5: 원격 정류장 탐색·검색 복귀, 미리 선택 후 저장, 최대 글자 크기·다크 모드·가로 화면 대기 시작을 검증했다. 스크롤 제스처가 하단 탭을 건드리지 않도록 테스트 좌표를 보정한 뒤 실패했던 시나리오를 재검증했다. 큰 글자·가로 화면에서는 탐색 조작부도 목록과 함께 스크롤된다.
