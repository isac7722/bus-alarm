# 버스 앱 디자인 기준

확정일: 2026-09-18. 기존의 파우더 블루 무광 입체 에셋 기준을 이 문서로 대체한다.

## 목표

**정류장·노선·도착 상태를 정확하게 전달하는 차분하고 깔끔한 앱.**

정보의 중요도는 글자 크기·굵기·간격으로 드러낸다. 파란색은 행동과 선택을 강조하는 데 사용한다. 화면을 장식하는 큰 버스 일러스트, 재질 표현, 강한 그림자는 사용하지 않는다.

## 요구사항 구체화

### 원래 요청

```text
위 느낌대로 정확한 정보를 주는 차분한 느낌으로 디자인 을 정하자

깔끔한 그런 느낌으로 



예전에 작성한 디자인 관련 다시 작성하고 새로운위 기준으로 그리고 

아이콘도 지금 기준에 어울리는 걸로 다시 만들고

그리고 전체적인 스타일도 새기준으로 가자

$clarify
```

### 확정한 범위

| 질문 | 사용자 결정 |
| --- | --- |
| 새 앱 아이콘 | 평면 버스 심볼. 단순하고 또렷한 형태, 그림자·입체감 최소화 |
| 화면 변경 범위 | 색상·아이콘·글꼴·여백 통일. 정보 순서와 버튼 배치도 필요한 만큼 정돈 |

- 디자인 문서, 앱 아이콘, 즐겨찾기, 정류장 찾기, 버스 선택, 대기 화면, 지도 조작부·마커, 실시간 현황에 적용한다.
- 정류장·노선·방면·도착정보와 기존 검색·저장·편집·대기 기능은 유지한다.
- API 계약, 데이터 저장 방식, 지도 묶음·분리 정책, APNs 동작은 시각 개편 때문에 변경하지 않는다.
- 완료 기준은 실제 화면에서 정보와 상태를 읽을 수 있고, 기존 동작 검증이 통과하며, 작은 화면·큰 글자·다크 모드에서도 핵심 작업을 수행할 수 있는 것이다.

## 색상

앱과 UIKit 지도, WidgetKit 확장에서 `ios/Shared/TransitColors.swift`를 공유한다. 화면별 임의의 파랑·청록·민트 강조색을 추가하지 않는다.

| 역할 | 밝은 화면 | 어두운 화면 |
| --- | --- | --- |
| 화면 배경 | `#F5F6F8` | `#151A21` |
| 카드·목록 표면 | `#FFFFFF` | `#202833` |
| 주요 글자 | `#252A32` | `#EDF0F4` |
| 설명 글자 | `#606975` | `#ABB5C2` |
| 행동·선택 강조 | `#42658C` | `#BED1E8` |
| 강조 버튼 안의 글자 | `#FFFFFF` | `#202833` |
| 선택 영역·보조 버튼 | `#E5EDF6` | `#2C3B4E` |
| 구분선 | `#DFE3E9` | `#3C4654` |

실시간 현황은 `#202833` 배경, 흰색 주요 글자, `#C1CAD5` 설명, `#BED1E8` 도착 시간으로 통일한다. Dynamic Island는 시스템의 검은 배경을 사용한다.

삭제·대기 종료는 시스템의 파괴적 동작 표현을 유지한다. 선택 상태는 색상과 체크 표시를 함께 사용한다. 노선·경고 등 의미를 가진 색은 정보 전달 목적에 맞게 사용한다.

## 글자와 정보 순서

- iOS 시스템 서체와 Dynamic Type을 사용한다.
- 화면 제목은 시스템 탐색 제목, 정류장 이름은 `title3`의 semibold, 노선 번호는 `headline`, 기본 정보는 `body`·`subheadline`을 사용한다.
- 설명은 `subheadline`, 보조 안내는 `footnote`, 갱신 시각 등 짧은 부가 정보는 `caption`으로 구분한다.
- 정류장 이름·방면은 줄바꿈을 허용한다. 숫자는 가능한 곳에 고정폭 숫자를 사용한다.
- 노선 번호와 도착정보가 가로로 들어가지 않으면 세로로 배치한다. 중요한 정보를 축약하거나 숨기지 않는다.
- 선택한 버스의 예상 도착, 정보 없음, 다시 연결 중, 종료를 구분한다. 갱신 실패에도 예정 시각까지 기존 카운트다운을 유지하며 자동 갱신 진행 문구는 추가하지 않는다. 알 수 없는 정보를 확정된 것처럼 표현하지 않는다.

## 표면과 조작

- 화면 좌우 여백은 20pt, 카드 내부는 16~20pt, 요소 사이 간격은 4/8/12/16/20/24pt를 사용한다.
- 즐겨찾기 격자는 기본 2열이며 접근성 글자 크기에서는 1열이다. 격자 화면 좌우는 16pt, 열·행 간격과 카드 내부는 12pt로 좁힌다. 카드 높이는 내용에 따라 늘리고 정류장명·방면·저장한 노선은 줄바꿈하여 모두 표시한다.
- 직접 제작하는 카드는 16pt, 버튼은 12pt, 번호 배지는 8pt 모서리 반경을 사용한다. 시스템 목록·탐색·시트는 네이티브 모양을 유지한다.
- 카드는 흰색 또는 어두운 표면과 얇은 구분선으로 나눈다. 자체 입체 효과·장식 그림자를 넣지 않는다.
- 한 화면의 주요 실행은 진한 강조 버튼으로 표현한다. 보조 탐색은 옅은 배경이나 텍스트 버튼으로 구분한다.
- 주요 버튼은 최소 48pt, 지도 마커·아이콘 버튼은 최소 44pt 터치 영역을 확보한다.
- 하단 실행 영역은 불투명한 표면과 얇은 위쪽 구분선으로 구성한다. 안전 영역과 스크롤 하단 여백을 지킨다.
- 비활성 상태와 처리 중 상태를 구분하고, 처리 중에는 기존 진행 표시를 유지한다.

## 아이콘

- 앱 아이콘은 밝은 회색 바탕의 차분한 블루 정면 버스 심볼이다. 제작 기록은 [앱 아이콘](../app-icon.md)을 따른다.
- 앱 내부는 SF Symbols의 평면 심볼을 사용한다. 같은 역할의 아이콘은 같은 이름·굵기로 반복 사용한다.
- 탭은 북마크와 버스, 지도는 버스, 선택은 원형 체크, 탐색은 화살표로 의미를 일관되게 전달한다.
- 빈 화면은 작은 심볼·제목·설명으로 구성한다. 새로운 장식용 대형 이미지를 추가하지 않는다.

## 화면별 적용

| 화면 | 정보 및 행동 순서 |
| --- | --- |
| 즐겨찾기 | 저장 개수·사용 안내 → 정류장 이름·번호·방면 → 저장한 노선 → 기다리기 → 정류장 추가 |
| 정류장 찾기 | 검색 → 지도/목록 전환·내 위치 → 지도 → 조회된 정류장 목록 → 번호·방면 확인 안내 |
| 버스 선택 | 정류장 정보·주의 안내 → 노선 번호·방면·다음 정류장·선택 체크 → 선택한 노선의 도착정보 → 저장 → 하단 대기 시작 |
| 즐겨찾기 대기 | 정류장 정보 → 오늘 선택할 버스와 도착정보 → 갱신 시각·저장 관리 → 하단 대기 시작 |
| 진행 중 대기 | 정류장 이름 → 노선별 시간 또는 상태 → 잠금 화면 안내 → 전체 종료 |

### 즐겨찾기와 버스 경로 — 2026-09-20

- 카드 본문은 상세 보기, 하단의 최소 48pt `바로 기다리기` 버튼은 저장한 버스 전체 대기 시작이다. 편집 모드에서는 하단 버튼을 삭제로 바꾸고 본문 이동을 막는다. 삭제 후 실행 취소와 저장 순서를 유지한다.
- 버스 경로는 처음에 전체를 표시한다. `내 위치` 요청이 성공하면 내 위치와 해당 노선의 가장 가까운 정류장을 함께 맞추고 하단 목록을 접는다. 목록은 주변 5km 이내 정류장을 직선거리순으로 보여주며 방면·정류장 번호를 함께 표시한다. 가장 가까운 정류장을 강조하되 승차 방향을 자동으로 선택하지 않는다.
- 가까운 정류장이 없으면 내 위치를 유지하고 안내와 `전체 경로 보기`를 제공한다. `전체 경로`는 노선 전체로 돌아간다. 주변 목록을 보더라도 경로선을 잘라내지 않는다.
- 실제 도로 경로 데이터는 실선, 정류장 좌표를 연결한 경로는 점선과 안내 문구로 구분한다. 표시 거리는 직선거리이며 도보 경로를 나타내지 않는다.
- 하단 목록과 선택한 정류장 영역은 손잡이 드래그·탭으로 접기/중간/펼치기를 조절한다. 접근성 글자 크기와 가로 화면은 지도/목록 전환을 제공한다.

지도에는 [마커 동작 계약](icon-and-map-refresh.md)을 그대로 적용한다. 목록 개수는 조회된 결과 수이며 지역 전체 정류장 수로 표현하지 않는다.

## 검증 기준

- 밝은/어두운 팔레트에서 본문·설명·버튼의 전경/배경 대비를 확인한다.
- 즐겨찾기 저장·재실행·선택·해제, 지도 묶음·분리·카메라 유지, 빈 검색, 가로 화면의 기존 테스트를 실행한다.
- 375pt 화면과 최대 접근성 글자 크기에서 줄바꿈·스크롤·하단 버튼 접근을 확인한다.
- 앱 아이콘은 1024×1024 불투명 PNG이며 작은 크기에서도 버스로 식별되어야 한다.
- 실제 APNs 전달과 잠금 화면/Dynamic Island 표시는 지원 기기에서 별도 확인한다. 시뮬레이터 UI 검사와 기기 검증을 구분해 기록한다.
